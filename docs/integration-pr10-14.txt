함수별 보존 기준

- process_exec: #10의 a/b/c, words/ad 변수와 토큰 분리, 용량 계산,
  load 뒤 스택 구성, 성공/실패 정리 흐름을 유지한다.
  #14의 128개 인자 지원을 결합했다. 배열만 임시 힙에 두어 커널 스택을 보호한다.
  빈 입력, 129개 이상, 한 페이지 초과 입력은 스택에 쓰기 전에 거절한다.
  setup_stack 이후 쓰기, 8바이트 정렬, argv NULL, rdi/rsi 설정을 유지한다.
  #11의 load 내부 인자 구성은 중복 적용하지 않는다.

- syscall_handler: #14의 create/open을 함수 안에 그대로 둔다.
  이전 통합에서 만든 open_file/close_file/read_file 보조 함수는 사용하지 않는다.
  #14의 SYS_OPEN 블록은 줄바꿈을 제외하면 원본과 완전히 동일하다.
  create에는 #10의 INT_MAX 크기 검사만 결합했다.
  halt/exit/wait/write는 #10/#11 기반을 추가하고,
  close/read는 #12/#13의 switch 분기를 추가했다.

- check_user_string: #14 구현과 설명이 원본과 동일하다.
  check_user_address: 기존 주소/매핑 검사를 유지하고 PTE 사용자 권한 검사만 추가했다.
  #10의 check_buffer가 이 검사 함수를 이용해 모든 페이지를 확인한다.
  read 목적지에는 쓰기 권한 검사도 적용한다.
  검증은 파일 시스템 잠금을 잡기 전에 끝난다.

- allocate_fd / syscall_close_all_files: #14의 함수, 이름, 설명, 흐름을 유지한다.
  차이는 NULL 테이블 검사와 128 상수를 FD_TABLE_SIZE로 바꾼 부분뿐이다.
  이 사실은 함수 본문 비교로 검증했다.

- exit_status: #14의 thread->exit_status를 실행 중 종료값으로 유지한다.
  process_exit에서 이 값을 #11의 child_status->exit_status에 복사한 뒤
  자원 정리와 종료 알림을 수행한다. 부모 wait가 읽는 것은 종료 기록이다.
  SYS_EXIT/주소 오류/사용자 예외가 같은 thread 종료값을 설정한다.
  종료 메시지는 process_exit에서 사용자 자식에 대해 한 번만 출력한다.
  process_exit의 void 반환형을 보완했다.

- fd_table: #14의 멤버 이름을 유지한다.
  #12의 동적 할당/해제를 연결하고 범위는 FD_TABLE_SIZE=130, 파일 FD 2~129로 통일했다.
  fd_Table과 fd_table을 중복해서 두지 않는다.
  테이블 할당 실패, 슬롯 부족, close, 종료 해제를 처리한다.

- filesys_lock: #14 잠금 이름/사용 흐름을 유지하고 static만 해제하여
  #10 ELF 로더와 공유한다. create/open/close/슬롯 부족 시 close/종료 정리가
  같은 잠금을 사용한다. syscall_close_all_files 선언을 헤더에 추가했다.

- exception.c: #14의 사용자 예외 종료 코드와 한국어 설명을 유지한다.
  page_fault는 사용자 오류이면 이 kill 경로로 보낸다.
  커널 오류의 진단 및 PANIC은 유지한다.

- 미지원 syscall: #14의 default -1 반환을 유지한다.
  이전 통합의 default exit(-1)과 의도적으로 다르다.
  fork/exec/filesize 등의 구현을 추가한 것은 아니다.
  read는 유효한 파일 FD/버퍼여도 -1, write는 stdout만 지원한다.
